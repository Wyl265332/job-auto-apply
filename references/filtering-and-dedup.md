# 筛选口径与四层去重

`scripts/pipeline.py filter` 实现了下面这套，配置在 `config.json` 的 `filters` / `keywords` 块。

## 一、列表级粗筛（顺序即优先级，命中即出局）

| # | 规则 | 说明 |
|---|---|---|
| 1 | 主键缺失 | 没有 `job_id` / `jobId` 的卡片直接丢。没有主键只能回列表按位置点，列表会漂移，必然成片失败 |
| 2 | 方向不对口 | 岗位名必须命中正向词表 |
| 3 | 精确黑名单岗位名 | **用精确黑名单，不要删掉整类关键词**。只想剔除「市场营销」就只写「市场营销」，把「市场」整个删掉会误杀其他市场岗 |
| 4 | 管理岗 | 部长 / 总监 / 总经理 / 副总 / 董事 / 总裁 / 首席 / 院长 / 书记 |
| 5 | 行业误伤词 | **最容易漏的一层**。正向词里有「综合」会把「XX资源综合利用有限公司」的冶金岗捞进来。工业词黑名单：作业区 / 工艺 / 工程师 / 技师 / 操作 / 维修 / 冶炼 / 电工 / 焊工 / 炉 / 化验 / 采矿 / 地质 / 勘探 / 轧钢 / 烧结 / 焙烧 / 熔炼 / 电解 / 制液 / 动力检维修 |
| 6 | 黑名单集团 | 工商全称 / 字号匹配，见 platform-iguopin.md |
| 7 | 学历 | 按需求定；常见排除 大专 / 中专 / 高中 / 初中 / 中技 |
| 8 | 招聘类型 | 只留校招 |

## 二、四层去重（缺一不可）

| 层 | 做法 | 为什么 |
|---|---|---|
| 1 | 平台自带已投标记（国聘 `applied != 2` 排掉） | 最省事，一次排掉大量无效卡片 |
| 2 | 后台已投记录（岗位名 + 公司交叉比对） | 平台标记有延迟，后台记录更准 |
| 3 | 本轮已处理结果的主键集合 | 断点续跑不重复投 |
| 4 | 同公司同岗位名只留一条 | 分页漂移会产生重复卡片 |

第 2 层的坑：企业全称是工商全称，而名单里可能是品牌简称，直接字符串相等命中为 0。
需要先剥离行政区划前缀与「股份 / 有限责任 / 分公司 / 科技 / 集团」等后缀，提取**字号**再匹配。

分级匹配**只做两级**：

- L1 全称相等
- L2 字号相等
- L3 包含匹配**必有误伤**（「广州医药集团」会误杀一批名字里带「医药集团」的公司），
  只输出供人工复核，不自动执行

## 三、JD 门禁（投递前最后一道，不可省）

列表标签不可信，**打开 JD 再决定投不投**。`pipeline.py` 的 `jd_gate(name, jd)`：

```python
text = name + " " + jd
# 1) 负向优先：命中「N年以上经验」→ 跳过
# 2) 正向：命中 届别 / 应届 / 校招 之一 → 放行
# 3) 都没命中 → 跳过
```

三条必须注意：

1. **一定要把岗位名 name 一起判**。届别词（如「2027届」）经常只出现在标题里，
   只拿 JD 正文判会大量误杀。
2. **只取 JD 正文**。页面头部 / 导航栏会 100% 误命中。
3. **未登录时智联 JD 被截断**，此时门禁结果不可信，先登录。

## 四、多份简历的选择

按 **JD 信号词命中数**比较，不用岗位名单条判断：

```
score = JD信号词命中数 * 2 + 岗位名信号词命中数
取 score 最高者；全 0 取 default
```

**禁止跨方向混投**——行政岗用内容简历投是硬性错误，不要为了成功率放宽这条。
两份简历各有自己的事实与数字，**同一份简历内部只能用一套数字，禁止跨版本混用**。

## 五、跨年 / 跨批次匹配的噪声（数据分析场景）

如果是拿历史数据做分析（而非投递），注意：

- 职位代码每年重排（实测同一岗位 2026 是 `...001`、2025 是 `...004`），**不能拿代码做跨年匹配**
- 序号后缀（一）（二）（三）也不稳定
- 只能按「用人司局 + 职位名称」匹配，且要接受一定的错配率，把命中率如实写出来
