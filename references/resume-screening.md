# 简历驱动筛选（防误投）

这是整套流程里**唯一拦住误投的环节**。没有 `resume_profile.json` 就等于裸投——
`workflow.py doctor` 会把它标为缺失。

## 为什么需要它

- 平台筛选标签不可信（智联 `et=5` 校招参数照样能漏进社招岗）
- 同名岗位差别巨大：「运营」可以是内容运营，也可以是电话销售
- 误投的代价不对称：投错一个岗，消耗的是**有限的投递配额**和**企业侧的印象**

## profile 结构

`resume_profile.json` 四块：

```jsonc
{
  "resume_default": "默认简历名",
  "resumes": [{"name":"简历A","signals":[...]}, {"name":"简历B","signals":[...]}],
  "hard":  { /* 硬性条件，任一不达标就跳过 */ },
  "soft":  { /* ability 加分 / bonus 加分 / veto 否决 */ },
  "apply_rules": { /* 校招/届别/经验负向 */ }
}
```

### hard（硬性，不给分、不通融）

| 字段 | 作用 |
|---|---|
| `education_min` | 学历门槛，低于就跳过 |
| `education_ban` | 学历黑名单（如只要本科就把「硕士/博士/大专」都列进去） |
| `graduate_years` | 目标届别 |
| `experience_max_years` | 可接受的工作经验上限（校招填 0） |
| `majors` | 自己的专业，用于判断 JD 的专业要求是否对口 |
| `major_any_ok` | 命中这些词 = 不限专业，放行 |
| `cities` | 可接受城市 |
| `salary_min` | 薪资下限 |

### soft（软匹配）

- `ability` —— 能力簇 → 关键词，命中就加分（每簇最多 +3）
- `bonus` —— 福利/加分项
- `veto` —— **否决词，命中直接出局**，最先判

`veto` 是最有用的一栏。例：只想做内容岗，就把
`["销售","电话销售","地推","业绩考核","酒量","夜班","长期出差"]` 全填进去。

### apply_rules

- `require_campus` —— 打开时，JD 必须出现届别/应届/校招才放行
- `campus_words` —— 放行词（**记得把自己的届别填进去**，如「2027届」）
- `neg_regex` —— 工作经验负向正则
- `min_score` —— 最低匹配分门槛

## 判定顺序

```
1. veto 否决词              → 命中直接出局
2. 校招 / 届别              → 没命中就出局（require_campus 打开时）
3. 工作经验负向正则          → 命中出局
4. 学历黑名单 + 学历门槛
5. 专业（JD 写了专业要求但不对口 → 出局）
6. 城市
7. 薪资下限
8. ability / bonus 加分
9. 按各简历的 signals 命中数选简历
```

**负向永远优先于正向**：一个岗位就算命中 10 个能力词，只要要求「3 年以上经验」就不投。

## 用法

```bash
echo '{"job":{"pk":"S1","name":"内容运营（2027届校招）","company":"X","city":"上海","salary":"6-9K"},
       "jd":"负责公众号运营与推文撰写，本科以上，专业不限，面向2027届应届生"}' \
  | python workflow.py screen --platform shixiseng
```

返回：

```jsonc
{"pass": true, "score": 6, "resume": "简历A",
 "reasons": ["命中：校招+应届+应届生", "内容生产(3)"], "veto": []}
```

`pass=false` 时 `reasons` 里会写明原因（如「要求工作经验：3 年以上相关经验」、
「城市不符：哈尔滨」、「命中否决词：销售、地推」），直接记进日志当未投原因。

## 实测过的判定样例

| 样例 | 结果 |
|---|---|
| 2027届校招 + 本科 + 专业不限 + 文案岗 | 放行，选内容简历，6 分 |
| 要求 3 年以上相关经验 | 拦截 |
| 大专以上学历 | 拦截（黑名单 + 门槛双命中）|
| 城市不在列表 | 拦截 |
| 电话销售 / 地推 | 拦截（veto）|
| 行政岗（考勤/档案/会务）| 放行，选行政简历 |
| 薪资低于下限 | 拦截 |
| 专业要求计算机但自己是文科 | 拦截 |

## 两个坑

1. **「不限」会污染学历判定**。`edu_level()` 必须取文中出现的**最高**学历档位，
   且只在「学历不限 / 不限学历」时才算不限——否则「专业不限」里的「不限」会把本科岗判成学历不达标。
2. **届别词经常只出现在岗位标题里**，JD 正文没有。判定文本用 `岗位名 + JD` 合并，
   只拿 JD 判会大量误杀。

## 红线

- profile 只能描述**真实情况**，不许为了多投而放宽
- 不编造经历去凑能力词；加分低就低，如实反映"这个岗位不太匹配"
- 禁止跨方向混投：行政岗用内容简历投是硬性错误
